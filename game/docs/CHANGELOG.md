# Changelog

## Unreleased

- **Every location is now reachable and illustrated:** the expansion grew the map to 45 locations while `frontend-godot/assets/locations/` still held 29 PNGs, so 16 places rendered as a bare name label where art should be. `tools/gen_missing_location_art.py` is now a general scene illustrator: it reads each location's `location_type` and description, picks one of 16 archetypes (wharf, deepwood, palisade outpost, terraced farmland, mountain village, trial peaks, canyon market, sea pavilion, pirate cove, coral prison atoll, open sea, forge city, fortress, shrine, rune undercroft, ascension stair) with a mood palette (dawn/day/dusk/night/storm/forest/undercroft/astral), and composes a deterministic, seeded plate from large silhouettes — layered ranges receding into fog, then landmarks (pagodas, hulls, battlements, stalactites, rune glyphs, gate rings) over mirrored water or haze, finished with a soft vignette, colour lift and film grain at the same 1512x1040 as the painted art. Every id that lacks a PNG gets the image plus its `.import` sidecar; it only ever writes missing files, and `--location <id>` redraws a named placeholder, so hand-made paintings can never be overwritten. `tests/test_location_artwork.py` pins the 1:1 id↔PNG contract (and the sidecar), so a future location cannot ship art-less. Two data bugs the sweep surfaced are fixed: `gate_array_approach` named a body realm (`"Nine Stars Dao Palace"`) that matches no realm id or display name, which made `TravelService._realm_ok` fail open and silently drop the endgame gate (now the canonical `nine_stars_dao_palace`), and `ancient_ruins` declared no `available_systems` at all (now explore/travel/combat/gather/dialogue, matching its content). `validate_all_game_data()` gained a `dead_travel_gate` check for unresolvable `minimum_realm` values, and `tests/test_locations_data.py` now proves every gate resolves, every location declares systems, and no location is walled behind a stricter gate than its own. The 16 generated plates are stand-ins: `frontend-godot/assets/locations/ART_PROMPTS.md` carries a ready-to-paste prompt for each of them (shared style block, negative prompt, and crop-safe composition rules), each derived from that location's own description, so the placeholders can be repainted one-for-one.
- **Painted portraits land in the picker (Godot client):** eight hand-painted cultivator portraits replaced their generated placeholders — Mortal Disciple, Sword Immortal, Demon Path Heir, Sword Maiden, Moon Palace Fairy, Poison Valley Disciple, Beast Tamer, and a new **Sect Patriarch** slot (the roster is now 21, eleven male / ten female). `tools/import_avatar_art.py` is the drop-in path for the rest: it hands each source to `frontend-godot/tools/import_avatar_art.gd` (a `.gdignore`'d engine-side helper, so no imaging library enters the project — Godot already reads every codec a painter hands over), crops, resamples with Lanczos, writes the `.import` sidecar, and records provenance in `frontend-godot/assets/avatars/art_manifest.json`: source file and sha256, shipped sha256, source size, and both halves of the crop (`spec` = what was asked for, `crop`/`face` = what the engine did), so a re-import can be diffed instead of trusted. The default `--anchor face` measures the subject's skin tones and frames a head-and-shoulders bust, because the picker draws 76px cells where a full-length figure reads as a smudge; painted backgrounds sometimes read as skin, so the tool reports where the face landed and takes explicit `zoom`/`top` overrides, and the eight landed crops were chosen that way. `art_manifest.json` is now the roster's other half: art absent from it is a generated placeholder, which is what lets `tools/gen_avatar_art.py` refuse to overwrite a painting and `tests/test_player_identity.py` pin placeholders pixel-for-pixel while pinning *provenance* for paintings (512px square, shipped bytes matching the recorded hash, and a crop that is a bust rather than a full torso — the last one would have caught the first, full-torso framing attempt). `AVATAR_BRIEF.md` regenerates with the live painted/placeholder split and the import workflow.
- **Player identity - choose your name and your face (Godot client):** the cultivator is no longer locked to "Daoist". The twenty portraits -- ten male, ten female, each a stock archetype of the cultivation-novel canon (the mortal-born disciple, the cold sword immortal, the nine-tailed fox spirit, the dragon princess) -- currently ship as deterministic **placeholders** drawn by `tools/gen_avatar_art.py` (pure-stdlib raster canvas, no new dependencies) into `frontend-godot/assets/avatars/<id>.png` with their Godot `.import` sidecars. They are flat paper-cut geometry, not painted art: `python tools/gen_avatar_art.py --brief` writes `game/docs/AVATAR_BRIEF.md`, the art spec plus twenty copy-pasteable prompts (framing, size, palette, per-character hair/eyes/robe/props) so the same roster can be painted as one family and dropped in file-for-file; `--only <id>` regenerates a single placeholder. A new shared picker (`IdentityEditor.gd`) is reachable four ways -- the top-rail portrait/name cluster, the dossier portrait, the Settings dialog, and the main menu -- with a name field, an ALL/MALE/FEMALE portrait filter, and a 5-column grid; a `PlayerProfile` autoload persists the choice in `user://profile.cfg`, feeds the name to NEW GAME, and dresses the top rail, the dossier, and the menu, falling back to a monogram when art is missing. The engine gained a turn-free `RENAME` action (whitespace-normalised, 24-character cap, `NAME_CHANGED` event with narrated prose) so a name chosen mid-life is written into the save rather than only into the client. `tests/test_player_identity.py` pins the roster (10/10, unique, snake_case ids), the committed art (256px RGB, distinct, each portrait's face matching its recipe's skin tone), the GDScript-roster/recipe parity, and the rename contract.
- **Removed the duplicate exits row under the location art (Godot):** the location panel offered two ways to travel — the clickable exit buttons sitting directly beneath the (cropped) artwork and the **Travel** action card. The buttons are gone; travel now runs only through the Travel card, which lists every destination with its danger rating and its lock reason.
- **G.2 dead-content sweep (new gate + the dead content it found):** `game/validation/dead_content.py` derives how every skill/item/equipment/enemy/NPC/quest/dao/recipe reaches a run and flags both unreachable entries and *trap options* (consumables whose effect the engine cannot resolve, equipment with no modifiers, materials with no effect/role/source, dead recipes, permanently locked quests, unsatisfiable NPC gates, dominated shop offers). It is wired into `validate_all_game_data()` and printable via `tools/dead_content_report.py`; `tests/test_dead_content.py` (17 tests) also proves every effect in the vocabulary really resolves in the system that owns it. Fixes it drove:
  - **148 of 236 random enemies were unfightable** (no encounter pool, no realm, no quest -- and every location has a curated pool, so the global fallback never fired). `tools/seed_enemy_pools.py` gives each stranded foe a realm-appropriate zone home (all 45 pools now 4-8 entries, 0 stranded), which also routes their loot tables into the world.
  - **Six item effects were advertised but never implemented** (`lifespan_extension` on 19 pills, `comprehension_boost`, `restore_hp_qi`, `cleanse_poison`, `body_temper`, `breakthrough_aid`): using those consumables burned the stack for nothing. `EffectSystem` now implements all six, and its `SUPPORTED_EFFECTS` vocabulary is the contract the sweep validates against.
  - **Nine materials** (`common_crystal`, `earth_scale`, `profound_star_core`, `mystic_essence_mortal`, `bone_forging_feather`, `dao_enlightenment_fruit`, `phoenix_marrow_blood_essence`, `phoenix_marrow_bone`, `immortal_ascension_scale`) had no effect, no recipe/upgrade role and no source -- they now absorb for cultivation progress like their siblings.
  - **60+ NPCs could never be met, sparred, dueled, or give boons:** their `unlock.min_stage` gate was compared against `player.stage`, which the cultivation system pins at 1. `CharacterService.required_story_tier` folds that legacy ladder onto the live story tier (`MAX_STORY_TIER`), keeping the author's intent without the dead gate.
  - **Endgame economy re-anchored:** widening the tier 5-6 encounter pools diluted spirit-stone income (ledger: 1175 -> 751 against a 930-stone hall). `tools/economy_tune.py` now gives every foe in a tier 5-6 zone that zone's going stone rate, restoring run income (~1178) with the same headroom as before.
- **Complete Godot GUI overhaul (the "Standing Door" canon):** rewrote `MainController.gd` and `MainMenuController.gd` around a committed visual world — warm lacquer-ink ground with a subtle grain texture, antique-gold double-rule frames, Cinzel display type + Alegreya Sans body (both OFL, license bundled at `frontend-godot/ui/fonts/OFL.txt`), and a rewritten shared theme (`martial_path_theme.tres`). The five former text-dump tabs are now purposeful spreads rendered from the full `/state` payload: Inventory (rarity-edged item card grid), Equipment (paper-doll slot wall + aggregated bonus tally), Journal (quest cards with real progress bars), Status (two-column character sheet), Techniques (skill cards with cooldowns). The main menu is a framed door panel with origin selection, a numbered past-life chronicle ledger, a gold primary NEW GAME, and the legacy unlock tree as a proper dialog (AWAKEN/OWNED/SEALED states) instead of a raw PopupMenu. Tab switching works from inside the overlay via its own header tab strip (the dim layer blocks the top-bar buttons — verified live). Design tokens and rules recorded in `DESIGN.md`; verified end-to-end with the godot-ai MCP loop (run → click → screenshot) across the menu, dashboard, and all five tabs.

- **Fixed `UPGRADE_TALENT` (and 9 other actions) silently failing through the API:** `ActionRequest` did not declare `track`, `target_id`, `sect_id`, `trainer_id`, `years`, `recipe_id`, `dao_id`, `unlock_id`, `rumor_id`, `payload`, or `choice_id`, so pydantic dropped them and the engine received empty arguments (e.g. talent upgrades with the Talent Refining Elixir always returned `INVALID_TALENT_TRACK`). The field list now mirrors every key the dispatch table reads, with a test pinning the full set.
- **`USE_ITEM` no longer fakes success on materials:** items with no effect (e.g. `talent_refining_elixir`) now return an honest `ITEM_NOT_USABLE` error without consuming the item or the combat turn; they are spent by their owning systems (talent upgrades, refining recipes).
- Fixed a truncated `Enemy.from_dict` constructor call (`game/models/enemy.py`) that broke all test collection.

- **A.6 voice consistency:** added `game/docs/VOICE_GUIDE.md` (tone rules + banned gamey terms) and `game/data/lore_glossary.json` (canonical lore terms seeded from real realm/dao/tier/season/morality labels, registered and validated). `narrative_lint` gained four checks — gamey-term blocklist, brace artifacts, ≥2 variants per verb, glossary conformance — all wired into `validate_all_game_data()`; `tests/test_narrative_voice.py` adds the 100-event sameness property test.
- **B.6 stances + combos:** techniques may carry `combo_role` (`opening`/`response`/`finisher`); three chains seeded on 9 skills. `CombatSystem` banks chains (+25% damage per banked stage, flowing into any damaging technique; neutral skills pass through without advancing/breaking), the engine refuses out-of-sequence chain skills without wasting qi and drops chains on combat end, and player/technique views expose `combo_stage`/`expected_combo_role`/`combo_ready`. Chain state is transient (reset each fight); `tests/test_combo_combat.py` covers it (17 tests).
- Added content-discovery systems so authored skills, items, and equipment are reachable in-game. Skills are now learnable two ways: **technique manuals** (a learn-skill item auto-generated for every skill, `id "<skill_id>_manual"`; `USE_ITEM` teaches and consumes it) with optional per-skill overrides in `data/technique_manuals.json`, and **trainers** (`data/trainers.json`) — location-bound masters that teach skills for Gold/Spirit Stones via `TRAINERS`/`LEARN_SKILL`. Exploration finds now draw a rarity-weighted, danger-gated item/equipment reward from the whole catalogue (`events.json` `find_config`), so higher-`danger_level` areas surface rarer gear. New `SkillSystem`, `TrainerSystem`, and `FindSystem`, a shared `currency` helper (shared with shops), central validation for trainers/manual-overrides/find_config, and a Godot "Masters" action to learn techniques.
- Gave Essence Gathering its own fatigue (`cultivation_strain`) and stability (`foundation_stability`) system mirroring Body Transformation: Essence training builds strain, Essence breakthroughs are gated by `max_strain_for_breakthrough` and `required_foundation_stability`, failed Essence breakthroughs raise strain and lower stability, successful ones relieve strain, and a new `STABILISE_ESSENCE` action (with `stabilise_essence` time cost) settles Essence strain and restores Essence foundation stability. Tuning lives in a new `essence_progression` config block (centrally validated); the Godot frontend shows Essence Strain/Stability and a Stabilise Essence action.
- Fixed exploration always surfacing named characters at their location: the encounter is now gated by a data-driven `character_encounter_chance` (`data/events.json`, default `0.35`), so exploring a location with named cultivators still rolls combat, loot, special, and quiet events instead of only the character encounter.
- Added normalized world-map coordinates to every location and a Godot World Map popup using `Sky Spill Continent Map.png`; the popup places a current-location marker from backend `location.map_position` state.
- Added data-driven shops and equipment purchasing: `game/data/shops.json` defines location-bound markets with stock and prices, `ShopSystem` validates `SHOP`/`BUY_ITEM` actions, Gold and Spirit Stones can be spent as currencies, and the Godot frontend now exposes a Market action that buys through the backend.
- Replaced the Spiritual Root and Physique traits with a unified two-track Talent system: new games roll an independent Martial Talent (essence aptitude) and Body Talent (body aptitude) from `cultivation/martial_talents.json` and `cultivation/body_talents.json`, named per the talent ladder grades (Common Grade splits into three sub-talents). Existing cultivation multipliers, weights, and upgrade hooks carried over unchanged; the player now stores `martial_talent_id`/`body_talent_id`.
- Added lifespan tracking: characters start at age 12 and age by a data-driven per-action time cost (`cultivation_config.json` `lifespan.time_costs`). Maximum lifespan follows the current Essence Gathering realm (`max_lifespan_years` per realm; mortal base 100), so breakthroughs extend it and `beyond_divinity` is effectively immortal. Reaching the cap ends the run with a `PLAYER_DIED` game-over. A pure `LifespanSystem` exposes read-only age/remaining-years views.
- Equipment now gates on actual cultivation (realm/stats) rather than talent: removed the `minimum_spiritual_root_rank` / `minimum_physique_rank` requirement checks.
- Bumped the save schema to version 2 (talent IDs + `age_years`); version-1 saves are rejected on load.
- Updated the Godot frontend to show Martial/Body Talent, current age/lifespan, and an old-age death screen.
- Added a data-driven two-track talent tier ladder (`cultivation/talents.json`): 20 tiers plus an Apex tier, each sharing one index across the Martial and Body-cultivation tracks and mapping to a reachable cultivation realm and maximum lifespan (canon lifespans flagged vs extrapolated). Loaded by `GameDataRegistry`, cross-checked by the central validator (unique ids/tiers, known essence-realm references, valid source flags, exactly one apex), and resolved through a pure read-only `TalentSystem` exposed as `engine.talents`.
- Added encounter-driven named character interactions: exploration can surface local named characters with Talk/Spar/Duel options; Talk returns dialogue context, while Spar/Duel validate character hooks and spawn named foe combat entries.
- Reworked enemies to use cultivation realms instead of numeric levels, expanded the random enemy roster with realm-based enemies, and made combat encounter pools location-specific across the world map.
- Added a data-driven equipment system with weapons, armor, boots, cloaks, rings, amulets, talismans, artifacts, and flying swords; equip/unequip actions validate inventory ownership, slots, requirements, and aggregate derived stat/cultivation modifiers without mutating base stats.
- Added data-driven starting fate: new games automatically roll and assign a Spiritual Root and Physique, save stable trait IDs, and apply trait multipliers to cultivation base gains, breakthrough odds, Body breakthrough stat gains, and strain/comprehension effects.
- Reworked cultivation pacing: Body and Essence realms now use data-driven increasing progress requirements; Body training builds strain and same-day diminishing returns, foundation stability gates breakthroughs, Stabilise Foundation recovers strain/stability, and permanent body stat gains are awarded only on successful breakthroughs.
- Added dual cultivation progression with separate Body Transformation and Essence Gathering tracks.
- Added data-driven cultivation realm files and shared cultivation config.
- Added pure cultivation state dataclasses with save-ready serialization.

### Codebase optimisation pass

- Added import and JSON-parse smoke tests, and ignored `frontend-godot/.godot/` editor cache.
- Added a central data validation layer (`game/validation/`) with `validate_all_game_data()` checking unique IDs and every item/enemy/character/location/encounter cross-reference; covered by `tests/test_all_game_data_valid.py`.
- Added `GameDataRegistry` (`game/data/registry.py`) as the single load point for all static content; `GameEngine.new_game` now builds from it and accepts an injected registry.
- Split large content into merge-on-load folders: `data/characters/*.json` (by faction), `data/enemies/random_enemies.json`, and `data/character_enemies/named_foes.json`; added `load_collection()` to the data loader.
- Migrated `locations.json` to the node-based schema (`display_name`, `zone`, numeric `danger_level`/`qi_density`, `connected_locations`, `npc_ids`, `requirements`, ...) and added a `TravelService` with requirement gating (realm/item/reputation) and reachable/locked destination listing.
- Added location-scoped encounter pools (`data/encounter_pools.json`); `EventSystem` now selects area-specific combat/loot/special content and falls back to global pools.
- Added a `CharacterService` coordinating NPC availability, dialogue context, morality band, and relationship tier; wired `MoralitySystem`/`RelationshipSystem` into the engine and exposed `location_characters` in game state.
- Moved passive skills from baked-in base stats to on-demand effective stats (`StatsSystem.effective_defense`); removed the `passives_applied` flag.
- Split save persistence into `SaveRepository` (I/O) and `SaveService` (versioning/validation); removed `systems/save_system.py`.
- Added typed result models (`game/core/results.py`); converted `Action`/`EventType` to `StrEnum`; refactored engine action dispatch to lookup tables and the command router to a data-driven argument map; fixed the GUI escape helper to use `html.escape`.
