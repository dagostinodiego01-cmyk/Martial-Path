# Changelog

## Unreleased

- **M1 save continuity & transport safety — a save now resumes the same run, in a new process (SV.1, SV.2, SV.5, SV.6, API.1-API.3):** the persistence layer stopped being the release blocker and became the thing the rest of the plan can stand on.
  - **Deterministic continuation (SV.5):** the snapshot now carries the run seed plus the full internal state of all five gameplay RNG streams (`main`, `narrative`, `foe_ai`, `debate`, `world`) via the new `RNG.get_state()`/`set_state()`, along with the seed-derived world variation (`dominant_sects`, economy band), the narrative system's stable-prose key, cooldowns, the pending-fate state, active secret realm, oath stakes, and the run's `running` flag. Previously a load silently reseeded every stream from the construction seed, so a fresh process diverged on the very next roll. The gate is `tests/test_save_continuation.py`: it replays a recorded log, saves at a safe point, loads the save **in a separate Python process built from an unrelated seed**, plays the remaining ~170 actions there, and asserts the event list and final state digest match the original run exactly — plus an in-process variant and a negative control that proves the comparison can fail.
  - **Migration instead of rejection (SV.1):** `SAVE_VERSION` is now 3 with a tested migration chain: v1→v2 renames the old Spiritual Root / Physique fields to the stable talent ids, v2→v3 installs the documented defaults for the new session fields, and `SaveService.write` migrates imported older payloads so a stale save can never be mislabelled current. Missing/absent/future versions still fail `SAVE_VERSION_MISMATCH`, and a non-integer version is `SAVE_CORRUPT`. A migrated v2 save loads with stable player/world state; only v3 saves promise bit-identical continuation (documented in `SAVE_SYSTEM.md`).
  - **Crash safety (SV.6):** `SaveRepository.write_raw` serialises before touching disk, writes to a fsynced `.json.tmp`, moves the previous save to `.json.bak`, then promotes — so every interruption window leaves the previous save recoverable, and `read_raw` falls back to the backup when the primary is missing or unparseable. A slot whose primary file vanished still lists from its backup; `.bak`/`.tmp` never appear as slots. Covered by serialisation-failure, simulated-crash, and corrupt-primary tests.
  - **Safe points and one autosave policy (SV.2):** `GameEngine.at_safe_point()` defines where saving may happen (exploration turns with no scene open, fate accepted); explicit saves outside it are refused with a legible `UNSAFE_SAVE_POINT` instead of silently dropping the fight on load, and `GameEngine.autosave()` fires only after a successful turn at a safe point. The API server calls it after every non-refused `/action`; refusals, mid-scene turns, and finished runs never autosave.
  - **Session ownership (API.2):** every engine-touching endpoint now holds a single session lock, so concurrent `/action`, `/save`, `/load` and `/new-game` are serialised rather than interleaved — single-session ownership for a local game, not network safety.
  - **Versioned action contract (API.1):** `game/api/action_contract.json` pins the `POST /action` field list, types and error codes; `ActionRequest` is checked against it in both directions, and unknown fields are now **422** (`extra="forbid"`) instead of silently dropped — the `itemId`-instead-of-`item_id` typo can no longer no-op a command.
  - **Live HTTP smoke (API.3):** `tests/test_api_live_http.py` boots a real `uvicorn` subprocess with hermetic saves and exercises state/action/save/load, the 422 contract violations, and a burst of concurrent mutations over actual HTTP.
  - Saves honour `MARTIAL_PATH_SAVE_DIR` (portable installs, hermetic tests — the suite no longer writes into the real save directory).

- **L4 economy & alchemy — every currency has an answer, and the alchemy loop says what it wants (EC.2, EC.4, EC.5, A.1, A.3, A.4):** the economy's acceptance criteria moved from "a tool prints OK" to gates the suite and the validator enforce, and the alchemy payload grew the joins the gathering/refining surfaces were missing.
  - **The state payload now carries two new read-only surfaces (A.1):** `gathering_here` — the current location's weighted herb table joined to the player's holdings (`held`), each herb's share of the table (`weight`), and every recipe it feeds (`used_in`), so a gathering panel can say "this ground pays spirit grass, you hold 2, it brews into a healing pill" without its own joins. It is gated by the same rule as the GATHER action, so it never advertises a fallback table the ground will not pay.
  - **Recipes carry their ingredient ledger (A.3):** every `refining_recipes` entry now includes `missing` (shortfall per input) and `brewable` (realm met *and* nothing missing) beside the existing realm gate, so the refine dialog's have/need rows and lock reasons render engine numbers instead of re-deriving them client-side.
  - **Currency clarity is payload, not folklore (EC.5):** `get_game_state()` carries `currency_guide`, the canonical gold-vs-stones explainer from `game/systems/currency.py` — the same module that enforces the spend/afford rules it describes — listing each currency's sinks (gold: shops, trainers, halls, repair, tolls; stones: technique halls, high-tier trainers, black markets). A new validator (`_validate_currency_economy`, wired into `validate_all_game_data()`) proves spirit stones have an authored sink anywhere in the world and that a gold sink is reachable over the location graph from the start by every story tier, so mid-game gold always has somewhere to go.
  - **Find-only is now a declared design tier (EC.4):** every item/equipment entry already had an authored acquisition path (zero unreachable since the rescue pass); what was missing was the guarantee it stays that way. `FIND_ONLY_ALLOWLIST` in `game/validation/dead_content.py` is the only way a find-only entry stays green; anything else whose only source is the generic find roll fails the sweep as `accidental_find_only`. The allowlist is reviewed (≤10 entries, all existing ids) and currently holds exactly one member: `spirit_stone`, which circulates as loot by design.
  - **No dead pills, measured (A.4):** the sweep grew `dominated_shop_pills`, the potency-ladder counterpart of the equipment domination rule — a consumable offer strictly beaten by a same-effect shelf-mate (stronger at a lower-or-equal price, or equal at a lower one) is a trap option. The first run found **9 real traps across 4 shop racks**: flat generator pricing had stacked 38/42/551-magnitude cleanse pills at one price and priced stronger pills below weaker siblings elsewhere. `game/data/shops.json` is repriced so each same-effect shelf is a strictly rising ladder; zero dominated pill offers remain, and the check rides in `validate_all_game_data()`.
  - **The band is locked (EC.2):** `tools/economy_report.py`'s verdict passes (priciest technique 180 vs a 294.5 budget; costliest hall 930 vs 1060.1), and `test_income_to_cost_band_holds` now pins the live income/expenses ratios *inside* the designed shares, so a content wave that quietly halves income or doubles a hall's tuition trips a balance alarm rather than only a reachability one.
  - The **render half** of A.1/A.3 belongs to the Godot panel lanes (L8): L4 supplies the payload fields and the data gates.

- **L2 combat & dao feel — the fight explains itself, and a retreat can save the run (CB.2, CB.5, CB.6, CB.7, D.3, D.4, D.5, D.7):** the round payload grew the readable layer the panels were missing, and three criteria that were previously asserted by eye are now measured by seeded simulations inside the suite.
  - **Statuses (CB.2):** `STATUS_RULES` in `game/systems/combat_system.py` is the one contract for a timed effect — label, icon, and **stacking rule**. A re-applied stun *refreshes* (longest duration, strongest magnitude) instead of chain-stunning into a stun-lock; a re-applied poison *stacks*, capped at three times the strongest single dose so layering cannot ratchet its own ceiling; a re-applied debuff keeps the strongest cut. `status_views()` turns the raw dict into ordered, labelled rows (harmful first) and rides on the combat payload, the player state (`status_views`), and every enemy view — so a panel renders "Stunned, 2 turns" instead of interpreting an effect key.
  - **Fight length (CB.5):** an even matchup measures 4-8 rounds (median 6) and can no longer grind: past `STALL_ROUNDS` (12) both sides tire — a `fatigue_scale` step that appears in the CB.1 damage breakdown, so the ramp is legible rather than mysterious — and `MAX_FIGHT_ROUNDS` (40) ends a bout as a `STALEMATE`: a draw with no loot and no defeat penalty, chosen over a silent hang. Every combat payload now carries the `round` clock and the player's `shield`.
  - **Formations (CB.6):** each entry in `enemies` is tagged with its `slot`, `is_leader` and `is_target`, and a `formation_state` summary names the leader, the current target, the `incoming` rest, and the `remaining`/`total`/`defeated` counts — at combat open, after a `TARGET_FOE` retarget, and on every resolved round (a solo fight reports `active: false, remaining: 1` rather than nothing at all).
  - **Retreat (CB.7):** `flee_chance()` publishes the odds before the player commits, and the escape is no longer a flat coin flip: a cultivator at or below 35% HP scrambles harder (+0.35, capped at 0.95). Measured over 200 seeded duels, fleeing at 30% HP saved the run **74% of the time before, 96% after**; the suite holds the ≥80% bar.
  - **Combo legibility (D.3):** `combo_view()` names the banked chain, the role it expects next, and the damage bonus the next technique will carry. An out-of-sequence refusal now reports the moved role, the expected role, the stage, the `banked` chain and the `bonus_forfeited`, with a plain-language `message` — the refusal explains the cost instead of only naming a rule.
  - **Insight (D.4):** `insight_view()` names all four sources with their drip rate (comprehension per round, landed hits, crits, counter wounds), lists the gated techniques the cultivator *actually knows* as spend targets with `required`/`ready`, and points at the `next_spend`. The `NOT_ENOUGH_INSIGHT` refusal carries the `shortfall` and the whole ledger. Pacing is tested, not assumed: a 30-comprehension cultivator reaches a 5-point gate inside one even fight.
  - **Foe AI fairness (D.5):** a guarded foe may shelter at most `GUARD_MAX_STREAK` (2) rounds in a row, so a turtling foe can always be broken, and desperation is capped (`MAX_AGGRESSION` 2.0) however favourable its matchup and however wounded it is. The audit measures seeded parity duels per dao-matchup band, and proves the hard tier is **never a trap**: against a sample of real High-tier foes, a cultivator who cuts and runs at 30% HP escapes at least four times in five.
  - **Dao balance (D.7):** a round-robin audit plays the same seeds once per dao against an identical foe roster, so the player's dao is the only variable, and holds every dao within ±10% of the median win rate; a companion test proves all eleven non-void daos are structurally interchangeable (each counters one and is countered by one). `void_dao`'s neutrality is measured as the top edge of the band — it never gains a counter bonus but is never countered either — and pinned as the first thing the S3 sweep should price.
  - **Reported rather than patched (S3's numbers, not L2's mechanics).** Two findings are recorded in `tests/test_foe_ai.py` instead of tuned here, because the plan makes balance a single serial sweep: (1) the shipped tier table is **Low 100% / Moderate 78% / High 0% / Deadly 0%** with a plain attacker, so *no* tier lands in 40-70% — the cliff sits exactly at the Moderate/High boundary, which is an HP-pool / `foe_power` (5x attack weight) problem, not a combat-mechanics one (`test_the_shipped_tier_table_is_reported`); and (2) at 1.5x/0.75x the dao counter graph **decides** a parity fight outright — 0% wins even with a +20% attack edge — recorded as a strict `xfail` that flips to a pass the moment the multipliers are softened (`test_a_countered_player_with_an_edge_can_still_win`).
  - The **render half** belongs to the Godot panel lanes (L8): L2 supplies the payload fields, and no client file was changed.

- **L3 funnel and encounters - the opening is now survivable (F.1, E.4, E.5, E.6, V.4):** a fresh character could walk out of `outer_forest` (danger 2) into `misty_gorge` (danger 4, 2.3x its power) or `ruined_shrine` (danger 6, **4.9x its power**, a story-tier-1 zone with no travel gate), and the deterministic playthrough died in 17 of 20 runs before it could reach story tier 2. Three fixes, all data-tunable:
  - **The funnel (`data/encounters.json` -> `funnel`):** while `max_story_tier < 2`, a hostile scene never fields a foe heavier than the player's own fighting weight. The drawn foe is swapped for one the location pool offers in band (the descriptor's prose is re-pointed at the substitute), packs are drawn from that same band (<= 0.6x the player), and the opening is never an ambush and never carries embedded hazard ground. If a pool has nothing in band, the lightest thing it has is sent rather than the worst. `pack_stat_scale` is now capped by danger too (0.5 at `danger_level <= 2`). The rule is the mercy counterpart of the existing hazard floor (`HAZARD_HP_FLOOR` = 1): the encounter layer never hands a first run a fight it cannot answer.
  - **Data:** `ruined_shrine` gained an in-band foe (its whole pool sat above a fresh player), and `tools/seed_enemy_pools.py`'s placement band was tightened from 3.5 to 2.0 danger so an endgame foe can no longer settle in the starting woods.
  - **Measured:** 200 seeded runs now give **192/200 (96%) reaching story tier 2** (was 6/20) and 183/200 alive at the action cap (was 3/20), with 0 dead actions; `tests/test_encounters.py` keeps a 30-run sample of the same gate.
- **Choices now lead with their stakes (E.4):** every encounter card carries the odds it runs on and the price of walking away - `odds` (threat band + foe/player power) on Fight, `chance` on Talk/Sneak/Pay/Push/Defuse/ambushed-Withdraw, `cost` on a toll, a trap-risk estimate on an unread find, the revealed effect on a studied site of power, and a `forfeit` line on Withdraw/Leave/Decline. Copy lives in `data/encounters.json` -> `stakes`; a check whose percentage the client already badges never repeats that number in its line.
- **The ground's consequence is carried into the next fight (E.5):** a hazard or trap that took HP is remembered and named in the next combat encounter's body text and on its Fight card (`wound`, with the damage taken and the HP it leaves you at), once - healing in between clears it. Hazard and trap damage still cannot kill; it floors at 1 HP and is handed to the fight, which is where lethality belongs.
- **Variety is measured (E.6):** `tools/playthrough_report.py` now prints the run-wide `event mix` (currently 6 kinds across 20 runs: character/combat/hazard/loot/nothing/special), and `tests/test_encounters.py` proves 100 explores in one zone surface at least five kinds including all four encounter kinds.
- **Difficulty curve audit (V.4):** `tools/seed_enemy_pools.py --audit` reports every zone's typical/weakest/strongest foe against the danger it advertises, rolls the table up per story tier, and flags `over_band`, `under_band` and `no_in_band_leader` (`--strict` exits non-zero on the two that matter). It currently flags three `over_band` zones (`nine_furnace_kingdom`, `southern_wilderness`, `planetary_gate_array`) and six `under_band` ones - left as *reported* debt for the S3 balance sweep rather than tuned here, since balance runs alone.

Every id that lacks a PNG gets the image plus its `.import` sidecar; it only ever writes missing files, and `--location <id>` redraws a named placeholder, so hand-made paintings can never be overwritten. `tests/test_location_artwork.py` pins the 1:1 id↔PNG contract (and the sidecar), so a future location cannot ship art-less. Two data bugs the sweep surfaced are fixed: `gate_array_approach` named a body realm (`"Nine Stars Dao Palace"`) that matches no realm id or display name, which made `TravelService._realm_ok` fail open and silently drop the endgame gate (now the canonical `nine_stars_dao_palace`), and `ancient_ruins` declared no `available_systems` at all (now explore/travel/combat/gather/dialogue, matching its content). `validate_all_game_data()` gained a `dead_travel_gate` check for unresolvable `minimum_realm` values, and `tests/test_locations_data.py` now proves every gate resolves, every location declares systems, and no location is walled behind a stricter gate than its own. The 16 generated plates are stand-ins: `frontend-godot/assets/locations/ART_PROMPTS.md` carries a ready-to-paste prompt for each of them (shared style block, negative prompt, and crop-safe composition rules), each derived from that location's own description, so the placeholders can be repainted one-for-one.
- **The portrait roster is fully painted (Godot client):** the thirteen remaining slots -- Azure Prodigy, Alchemist Sage, Dharma Monk, Thunder Sovereign, Beast-Blood Hunter, Young Master, Wandering Swordsman, Nine-Tailed Fox, Jade Sect Mistress, Phoenix Heiress, Ice Phoenix Princess, Rogue Swordswoman, Dragon Princess -- now carry hand-painted art, so all 21 portraits in the identity picker are paintings and `tools/gen_avatar_art.py` writes nothing (it keeps every slot it finds painted; the generated placeholders remain only as the fallback a slot would fall back to). Two importer rules came out of this drop and now hold for every future one: **`--size` is a cap, not a target** (the client's largest portrait is 76px, so a 192x338 source ships at 192 rather than being stretched into a soft 512 — `art_manifest.json` records `size` beside `size_cap`, and the crop-resolution floor is the check that a portrait is not an upscaled blur), and **alpha is flattened to RGB** on import, because the client draws portraits opaque and cover-cropped, where a transparent pixel is a hole in the tile. The framing lesson from the first drop repeated itself: these sources are already busts, but on one of them the face detector framed a face-only close-up while every sibling showed head and shoulders, so that slot was re-framed explicitly — the manifest's `spec`/`crop` pair is what makes such a fix a one-line re-run rather than a re-import of the set.
